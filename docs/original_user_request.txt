<USER_REQUEST>
You are a senior software architect, senior full-stack developer,
database engineer, UI/UX engineer, security engineer, QA engineer,
and AI integration engineer.

Your task is to design and build WORKPULSE, a production-quality
organizational workflow and activity management platform.

IMPORTANT:
This is a serious real-world software project and final-year project.
It must NOT be treated as a simple demo, tutorial, mockup, or collection
of disconnected screens.

The system must have a coherent architecture where authentication,
authorization, organizations, users, roles, departments, responsibilities,
request types, tasks, workflows, permissions, dashboards, notifications,
analytics, audit logs and Pulse AI all work together.

====================================================
1. PROJECT NAME
====================================================

WORKPULSE

Working description:

"An AI-enhanced organizational workflow, request and activity
management platform."

The system helps organizations digitally manage departments,
employees, requests, tasks, workflows, communication, organizational
knowledge and operational activities.

It must be configurable so that different organizations can define
their own departments, responsibilities, request types, task types
and workflows without changing the application's source code.

====================================================
2. CORE DESIGN PRINCIPLE
====================================================

WORKPULSE MUST BE CONFIGURATION-DRIVEN.

Do NOT hard-code departments such as:

- IT
- Finance
- HR
- Sales

into the application logic.

Instead, departments are created and configured by authorized
administrators.

The organization defines:

Organization
    ↓
Departments
    ↓
Department responsibilities
    ↓
Request types
    ↓
Task types
    ↓
Workflows
    ↓
Employees
    ↓
Managers
    ↓
Permissions
    ↓
Operational data

The same WorkPulse application must be capable of supporting
different organizations with different organizational structures.

====================================================
3. USER ACCOUNT PRINCIPLE
====================================================

Users register/create accounts through the appropriate registration
process.

A normal user MUST NOT be allowed to choose:

- Super Administrator
- Organization Administrator
- Department Manager

for themselves.

The backend determines the user's role.

The Super Administrator or authorized administrator assigns
organizational roles and departments.

Example:

User:
Muhammad

Email:
muhammad@company.com

Role:
Department Manager

Department:
IT

The user does NOT type "IT Manager" during login.

The backend stores and enforces this relationship.

====================================================
4. PRIMARY ROLES
====================================================

Implement these primary roles:

1. SUPER ADMINISTRATOR
2. ORGANIZATION ADMINISTRATOR
3. DEPARTMENT MANAGER
4. EMPLOYEE

Pulse AI is NOT a normal human role.

Pulse AI is an AI service/assistant operating through controlled
permissions and authorization.

Do not create a fake "Pulse AI user account" that bypasses security.

====================================================
5. SUPER ADMINISTRATOR
====================================================

The Super Administrator controls the WorkPulse platform and
organization configuration.

Capabilities may include:

- Manage organizations
- Manage users
- Manage roles
- Manage permissions
- Create departments
- Configure departments
- Assign department managers
- Assign employees to departments
- Configure organizational settings
- View system-wide audit logs
- Manage security settings
- Manage AI configuration
- View system-wide analytics

The Super Administrator is NOT automatically allowed to perform
every business operation unless the permission model explicitly
allows it.

Keep system administration and business responsibility logically
separate.

====================================================
6. ORGANIZATION ADMINISTRATOR
====================================================

The Organization Administrator manages the organization's internal
structure and users.

Capabilities may include:

- Manage employees
- Manage departments
- Assign employees
- Configure department information
- Manage organizational request types
- Manage organizational workflows
- View organization-level reports
- Manage organizational settings

Exact permissions must be controlled by the authorization layer.

====================================================
7. DEPARTMENT MANAGER
====================================================

A Department Manager manages ONE assigned department by default.

Example:

Muhammad
Role = Department Manager
Department = IT

The manager should see the IT operational environment.

The manager can:

- View department requests
- Review applicable requests
- Approve/reject requests where authorized
- Assign tasks
- Monitor team activities
- Update task status
- View department reports
- Manage department workflows where authorized
- Escalate requests
- Monitor department performance

A Department Manager must NOT automatically have access to
another department's private operational data.

Example:

IT Manager must not automatically access Finance requests.

====================================================
8. EMPLOYEE
====================================================

Employees can:

- Submit requests
- View their own requests
- View request status
- View assigned tasks
- Update assigned task progress
- Receive notifications
- Communicate where permitted
- Access authorized organizational information
- Use Pulse AI

Employees must only access data allowed by the authorization system.

====================================================

12. AUTHENTICATION
====================================================

Use secure authentication.

After successful authentication:

1. Identify user
2. Retrieve user account
3. Retrieve role
4. Retrieve organization
5. Retrieve department assignment
6. Retrieve permissions
7. Establish authenticated session/token
8. Determine authorized application context
9. Load appropriate dashboard

Example:

Muhammad logs in.

Backend determines:

User:
Muhammad

Role:
Department Manager

Department:
IT

Therefore:

Load:
IT Department Manager Dashboard

The user should NOT select:

[ IT Manager ]
[ Finance Manager ]
[ HR Manager ]

from the login page.

====================================================
13. AUTHORIZATION
====================================================

Authorization MUST happen on the backend.

Do NOT rely only on:

- hidden frontend buttons
- frontend routes
- local variables
- client-side role checks

Frontend checks may improve UX, but backend authorization
is the actual security boundary.

Every protected API/resource must verify:

- authenticated user
- role
- permissions
- organization
- department scope
- resource ownership where applicable

Example:

Muhammad:
Role = Department Manager
Department = IT

Request:
GET Finance private requests

Backend:
DENY

Even if the user manually modifies a URL or API request,
the backend must reject unauthorized access.

====================================================
14. ROLE + DEPARTMENT + PERMISSION MODEL
====================================================

Do not treat "role" as the only authorization factor.

Use:

USER
    ↓
ROLE
    ↓
PERMISSIONS
    ↓
ORGANIZATION SCOPE
    ↓
DEPARTMENT SCOPE
    ↓
RESOURCE ACCESS

Example:

Muhammad

Role:
Department Manager

Department:
IT

Permissions:

- view_department_requests
- review_department_requests
- assign_tasks
- manage_department_tasks
- view_department_reports

Scope:

IT Department

Therefore Muhammad can manage IT operations but not Finance
operations.
